# Archiver Dashboard - Information Source Pages

**The InfoSource and SourceRevision screens, and the routes behind them.** Split out of
[PAGES.md](PAGES.md), the per-page inventory, when that file passed its context budget; same
living-doc rule: a change to an `info_sources/` or `source_revisions/` template or a
`/dashboard/info-sources/` or `/dashboard/source-revisions/` route updates this file in the same
commit. Shared mechanics: [UI.md](UI.md), [HTMX.md](HTMX.md).

## Information Sources (`/dashboard/info-sources/`)

**GET `/dashboard/info-sources/`** - paginated list. Query params: `url_contains` (ilike filter on the `url` column), `limit`, `offset`.

**GET `/dashboard/info-sources/new`** - create form. Fields: `url` (text input) + `source_specs` (JSON array textarea, validates JSON on blur); its hint names the family rule: `css` (HTML), `xpath` (HTML and XML) or `jsonpath` (JSON), with `full_page` pairing with either (#356).

**POST `/dashboard/info-sources/new`** - form fields: `url` (string), `source_specs` (JSON array string). Calls `create_info_source`. 303 to detail on success; re-renders the form with an `errors` dict on `InvalidUrlError`, `InvalidSourceSpecError`, `MixedAlgorithmFamilyError`.

**GET `/dashboard/info-sources/{id}`** - detail page. Sections:

- The stored-document notice (§ Home), when `source_specs` fails the current schema.
- Header: `.entity-card` (SCREENS.md § **Header**, `#info-source-heading`, #79) - eyebrow "Information Source", the `url` in `<code>`, copyable `info_source_id`, then the **domain pill**: `domain_name` as a `.badge--primary` linking `/dashboard/domains/{name}`, or a `.badge--muted` "No domain" where the column is null - a state of its own, not an absence (#185). `open_button` is the header's action slot. `.detail-grid` (created_at UTC).
- Source Specification editor - the `info_sources/_source_specs_card.html` partial, extracted so the update-specs action can swap it in place (root `#source-specs-card`, heading `#source-specs-heading`, titled "Source Specification"). `sourceSpecsCard(startEditing)` (`main.js`; not in the COMPONENTS.md catalogue - it exists only for this card) gates it: **view mode** (`x-show="!editing"`) renders `source_specs` in `<pre class="code-block">`, edit mode the textarea form. All three buttons share one `.entity-card__actions` slot in the `.entity-card__header` (#185): **Edit** (`x-show="!editing"`); **Cancel** (`btn--secondary`, for border parity with the `apiKeyRow` Cancel - `@click="cancel()"` restores the stored specs and returns to view mode with no server call); **Save**, which submits the `POST .../source-specs` replace via `form="source-specs-form"` - it renders outside the `<form>`, so without that association it is inert with JS off. `specs_error` opens the card in edit mode (`sourceSpecsCard(true)`) so the error and the submitted text stay visible. The URL is immutable.
- **Viewport Capture** (archiver#380) - the `info_sources/_capture_card.html` partial (root `#capture-card`, heading `#capture-heading`), rendered only while `ARCHIVER_CAPTURE_ENABLED` is set. One builder, `_capture_context`, spread by every render site (the detail page, the specs editor's 422 fallback, the policy POST's 422 fallback, the poll and the POST) and registered in `tests/dashboard/test_partial_contracts.py`. The source's latest `capture_commands` row renders as one of: *Not captured yet*; *Capture pending* (requested age; the card polls itself every 5 s with `hx-sync="this:abort"`, the button syncs `closest #capture-card:drop`, archiver#220); *Stored* (rendered age, image size in px, file size, expiry UTC or an `expired` pill - or, once persisted (slice B), *Kept permanently, since* `persisted_at` UTC in its place - the landed `final_url` with `open_button`, copyable digest and `blob_uri` - *Kept at* the URI it is kept at once persisted (`permanent_store.kept_capture_uri`: `co-gcs-captures` for a capture stored there, else Replicator's permanent store), since the temp URI goes with the temp store) - and **the image** (slice D, D4): an `<img>` (`loading="lazy"`, intrinsic size, `alt` naming the URL and pixel size) from the image route below inside `.capture-image`, a bounded scroll region (STYLE.md), with an *Open full size* link beneath, because a full-page capture can be tens of thousands of pixels tall. No image, and a muted line saying why, for a capture stored before captures had their own bucket (it sits beside raw downloads Archiver may not read) or with no capture reader on the server; an expired, unkept capture shows none and no line (the `expired` pill says it); *Capture failed* (`reason` in `<code>` verbatim, `HTTP <status_code>`, `detail`); *No answer* (abandoned after the 60 min horizon; names `content.capture.dlq`). Under any state, a muted line (slice C) says what the command sent - `390×844, viewport only, once #main is visible` - and why: *on demand*, or *on a new revision* linking `/dashboard/source-revisions/{id}` (the capture renders the live page around it), plus *attempt N of 3* once the reaper has re-issued it. **Capture now** in the header's action slot is disabled while pending.
- **Capture Policy** (archiver#380 slice C) - the `info_sources/_capture_policy_card.html` partial (root `#capture-policy-card`, heading `#capture-policy-heading`), below Viewport Capture and on the same switch. Its own card because Viewport Capture swaps itself every 5 s while pending, which would wipe an edit. One builder, `_capture_policy_context` (registered in `tests/dashboard/test_partial_contracts.py`). States the effective policy - *No policy: Capture now sends the default* 1280×800, full page, after load, or the stored profile - and whether *each new revision is captured* or *on demand only*; a stored policy that no longer validates reads as an error instead. **Edit policy** is a native `<details>` (open while `policy_error` is shown) holding the form: viewport width and height, the wait (`after load` / network idle / a visible selector / seconds after load) with its selector and seconds fields, and checkboxes *Full page* and *Capture each new revision*. **Save**; **Clear policy** only while one is stored.
- Other Sources at This URL - shown only when other InfoSources share this `url` (the model allows several sources per URL, #79 #8); count in the heading, capped at 50 via a `limit+1` probe and rendered "50+" beyond that, each linked by `info_source_id` with its created date UTC.
- Bound Information Items - table of active `info_item_sources` bindings (count in heading; item name link, bound date UTC).
- Revision History - last 50 `source_revisions` ordered by `captured_at desc, source_revision_id desc` (count in heading; fingerprint truncated, captured date UTC, cache status pill).

**POST `/dashboard/info-sources/{id}/source-specs`** - replaces the `source_specs` list on an existing InfoSource (form field: `source_specs` JSON array). An **editor card** (SCREENS.md § **Editor cards**) against `#source-specs-card`, error key `specs_error` (#79 #7). Rejections: JSON parse failure, schema validation, mixed algorithm family.

**POST `/dashboard/info-sources/{id}/capture-policy`** - saves the form as the source's `capture_policy` (fields `width`, `height`, `wait_kind`, `wait_selector`, `wait_seconds`, checkboxes `full_page`, `on_revision`; only the field the chosen wait uses is read), or clears it with `action=clear`. An **editor card** (SCREENS.md § **Editor cards**) against `#capture-policy-card`, error key `policy_error`: success swaps the card with `showFlash` (success) and moves focus to the heading; a refusal (not a whole number, a side outside `1..4096`, a blank selector, a delay over 30 s or not a number) comes back at 200 with the input echoed and nothing stored. Without JS: 303 to detail, or a full-page 422. Sends no capture. 404 while `ARCHIVER_CAPTURE_ENABLED` is off or for an unknown source.

**GET `/dashboard/info-sources/{id}/captures/{command_id}.png`** - a stored capture's PNG (archiver#380 slice D, D4), read with `src/core/capture_reader.py` from `co-gcs-captures` only - kept, from where it is kept; else from the temp store until `blob_expires_at` - size-capped and hash-checked against the digest, then served `image/png` with `Cache-Control: private, max-age=31536000, immutable`, `ETag` the digest (a matching `If-None-Match` is a 304 with no read) and `X-Content-Type-Options: nosniff`. 404 while the switch is off, for an unknown source or another source's command, for a capture not stored, not a PNG, stored before the split, or expired and unkept, with no reader, or on a failed read or hash check.

**GET `/dashboard/info-sources/{id}/capture`** - the Viewport Capture card alone, the response of its own poll (`swapped` false, so a poll never moves focus). 404 while `ARCHIVER_CAPTURE_ENABLED` is off.

**POST `/dashboard/info-sources/{id}/capture-now`** - outboxes one `content.capture` command with its `capture_commands` row (`requested_by` the operator) in one transaction ([BUS.md](BUS.md)). HTMX (`hx-target="#capture-card"`, `outerHTML`): the card swapped in place, `swapped` true so focus moves to `#capture-heading`; a click while one is pending writes nothing and rides `HX-Trigger: showFlash` (warning); a stored policy that no longer validates, or a write failure, likewise (error). The command sends the source's capture policy, or the default. Without JS: a plain POST → 303 to detail; there a refusal is silent (no flash), and the re-rendered card shows the pending command. 404 while the switch is off or for an unknown source. No request body.

## Information Source Revisions (`/dashboard/source-revisions/`)

**GET `/dashboard/source-revisions/`** - paginated list ordered by `captured_at desc, source_revision_id` (ascending tiebreak, unlike the InfoSource list above and the InfoItem list in [PAGES.md](PAGES.md)). Optional `info_source_id` filter (ULID). Columns: truncated fingerprint (link to detail), source URL (link to InfoSource detail), captured date, cache status pill (`.status-pill--cached` / `.status-pill--expired` / `.status-pill--missing`).

**GET `/dashboard/source-revisions/{id}`** - detail page, and the reference implementation of the SCREENS.md conventions. The header lives in `source_revisions/_detail_card.html`, extracted so clear-cache can swap it in place (root `#revision-card`): `.eyebrow` "Information Source Revision" above an `<h1>` titled with the copyable `source_revision_id`. `.detail-grid` carries the copyable full fingerprint and the Information Source on `.detail-grid__item--full` rows so long values extend horizontally; the Information Source value holds the internal source-detail link plus an `open_button` to the target URL. Then captured_at (UTC), size and media type (each if set), and cache status - a status pill plus the `content_cache_uri` (`open_button` when `http(s)`, otherwise copyable) and an expiry line. "View all revisions for this source →" deeplinks the list as `?info_source_id=`. A danger-zone clear-cache form shows only when `content_cache_uri` is set.

**POST `/dashboard/source-revisions/{id}/clear-cache`** - sets `content_cache_uri = NULL` and `content_cache_expires_at = NULL`. HTMX requests (`hx-post`, `hx-target="#revision-card"`, `hx-confirm`) get the re-rendered `_detail_card.html` swapped in place plus an `HX-Trigger: showFlash` success toast; non-HTMX requests fall back to a 303 to detail. No request body required.
