{#- The Replication section's Fields block (archiver#307) - included by info_items/detail.html and returned by GET .../rep-fields (the re-fetch) and by a successful PATCH .../rep-fields (the save, re-targeted here). Requires `item_id`, `rows`, `other_fields`, `bag_json`, `selected` and `focus_input`, from every render site, by spreading `_rep_fields_context` (tests/dashboard/test_partial_contracts.py, archiver#219). Without `rows` the block renders "nothing required" for an item whose specs do require fields - a section that looks right and is not. `swapped` is the caller's: the save sets it so focus moves to the heading; a re-fetch on a sibling's event must not take focus from where the operator is. `selected` is the spec chosen in the picker (archiver#308): its keys join the rows, and the block carries it - in its re-fetch URL and as a hidden `selected_spec` in both forms - so a save or a sibling's re-fetch keeps it. `focus_input` is set only by the picker's Select, naming the first input that spec still needs. **Its own swap target, outside the assignments table.** The table polls every two seconds while a command is open; were this block inside it, a tick would discard a half-typed value. It re-fetches itself instead on `replicationChanged` from a sibling - the filter skips its own save, whose response already swapped it (docs/UI.md § Blocks that share a section). One row per raw key the specs require: the operator types `org.title`, the spec requires `org.title_slug`, and the row shows the slug. Each row's status cell (`_rep_fields_status.html`) is re-rendered out of band by the live readout as the operator types. -#}
